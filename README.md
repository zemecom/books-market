# Books Market

**Books Market** — это веб-приложение для управления каталогом книг и авторов, построенное на базе фреймворка Yii1.

## Возможности приложения

- **Каталог книг и авторов**: просмотр, добавление, редактирование и удаление книг.
- **Подписки**: возможность подписаться на любимых авторов по номеру телефона.
- **SMS-уведомления**: автоматическая отправка SMS-уведомлений подписчикам при публикации новой книги автора (интеграция с сервисом SMSPilot).
- **Отчеты**: просмотр списка топовых авторов (с нумерацией мест).
- **Ролевая модель**: разделение прав доступа для гостей, пользователей каталога и администратора.
- **Журнал SMS**: у администратора есть отдельная страница `SMS Logs` с историей отправки уведомлений.

## Запуск проекта

Самый быстрый способ развернуть проект с нуля — использовать команду `make init`. Она скопирует конфигурацию из `.env.example`, поднимет Docker контейнеры, установит зависимости через Composer, применит миграции и наполнит базу тестовыми данными (фикстурами).

```bash
make init
```

Приложение будет доступно по адресу [http://localhost:8080](http://localhost:8080).

### Учетные данные для входа

- Обычный пользователь: `user` / `user123`
- Администратор: `admin` / `admin123`

## Ролевая модель

В приложении есть три уровня доступа: `guest`, `user` и `admin`.

### Guest

Гость работает с публичной частью приложения без авторизации:

- просматривает каталог книг и карточки книг;
- просматривает список авторов и карточки авторов;
- открывает публичный отчет `Top Authors`;
- может подписаться на автора по номеру телефона.

Гость не может создавать, редактировать и удалять книги и авторов, а также не имеет доступа к административным страницам.

### User

Роль `user` предназначена для работы с каталогом. После входа пользователь получает все возможности гостя, а также может:

- создавать, редактировать и удалять книги;
- создавать, редактировать и удалять авторов;
- обновлять данные существующих подписок через интерфейс автора.

При этом `user` не имеет доступа к странице `SMS Logs` и не может удалять подписки.

### Admin

Роль `admin` является надмножеством `user`, то есть администратор наследует все возможности обычного пользователя и дополнительно может:

- открывать страницу `SMS Logs` (`/log/index`) и просматривать журнал отправки SMS-уведомлений;
- удалять подписки авторов.

Именно этим `admin` отличается от `user` в текущей версии проекта: у него есть доступ к журналу SMS и дополнительное административное действие по удалению подписок.

## Полезные команды (Makefile)

В проекте настроен `Makefile` для удобной работы. Основные команды:

- `make up` — поднять контейнеры в фоновом режиме.
- `make down` — остановить контейнеры.
- `make rebuild` — пересобрать и перезапустить контейнеры.
- `make migrate` — применить миграции базы данных.
- `make fixture` — загрузить фикстуры (тестовые данные) в БД.
- `make cs-fix` — запустить PHP-CS-Fixer для форматирования кода по стандарту.
- `make shell` — зайти в shell контейнера `app`.
- `make logs` — посмотреть логи приложения и БД.

Полный список команд можно получить, выполнив просто `make` или `make help`.

## Git hooks

Версионируемые git hooks лежат в папке `.githooks`, чтобы их можно было хранить в репозитории, а не только в локальном `.git/hooks`.

Подключить их в текущем клоне можно командой:

```bash
make install-git-hooks
```

Эта команда выставит локальный git-параметр `core.hooksPath=.githooks`, после чего Git начнет использовать хуки из репозитория.

## Тестирование

Для тестов используется Codeception. Тестовая база данных `books_catalog_test` создается автоматически при инициализации MySQL контейнера. Перед запуском тестов `Makefile` автоматически подготавливает базу.

Запустить все тесты:
```bash
make test
```

Только unit-тесты:
```bash
make test-unit
```

Только acceptance-тесты:
```bash
make test-acceptance
```

Для проверки шаблона в SMSPilot:
```bash
make sms-test
```

## Настройка SMSPilot (Переменные окружения)

Настройки хранятся в файле `.env` в корне проекта (создается автоматически из `.env.example` при `make init`).

Основные переменные для SMS:
- `SMS_TRANSPORT` (например, `smpilot` или `fake`)
- `SMSPILOT_API_KEY` — ключ API
- `SMSPILOT_TEST` — `1` для тестового режима (без реальной отправки), `0` для боевого
- `SMSPILOT_SENDER` — имя отправителя (если есть)
- `SMSPILOT_TEST_PHONE` — номер телефона для тестирования отправки

Для реальной отправки убедитесь, что `SMS_TRANSPORT=smpilot`, `SMSPILOT_API_KEY` заполнен и `SMSPILOT_TEST=0`. После изменения `.env` перезапустите контейнеры: `make rebuild` или `make up`.

## Архитектура и стек

- **Web-фреймворк**: Yii1 (controllers, forms, AR-модели, views).
- **Бизнес-логика**: Вынесена в application/domain services (например, `CreateBookService`, `NotifyBookSubscribersService`).
- **DI/IoC**: `ServiceContainer` собирает репозитории, command/query сервисы и инфраструктурные адаптеры.
- **Разделение**: Query side отделена от command side через специализированные read repositories.
- **Доменная область**: Выделены отдельные сущности, такие как `PhoneNumber` и `PhoneNormalizer`.
- **Интеграция**: Отправка SMS изолирована интерфейсом `SmsSenderInterface`. Для локальной разработки и тестов доступен fake transport.

## Компромиссы

Вместо `PHPUnit 13.1` используется `PHPUnit 12.5`, так как в текущем наборе зависимостей `Codeception 5.3` и инструменты coverage стабильнее работают с этой версией. Остальной стек (PHP 8.2+) максимально актуализирован.
